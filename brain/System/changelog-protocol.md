# Журнал изменений по проектам

**Приказ владельца 02.08.2026:** на каждый проект создаются файлы, где записываются все изменения,
которые были сделаны на проекте, чтобы потом было видно, что и как менялось раньше — в том числе
при работе с разных аккаунтов, где хотя бы общая картина изменений должна быть доступна.

Связано: [[decision-gate]] · [[memory-protocol]] · [[token-rules]] ·

## Где лежит

`brain/Changelog/<проект>.md`, один файл на проект. Карта.

Почему в мозге, а не в папке проекта: папки проектов пересобираются, клонируются и чистятся,
а мозг это слой памяти, который читается в начале каждой сессии и уезжает в git. Журнал в папке
проекта исчезает вместе с папкой ровно тогда, когда он нужнее всего.

Гранулярность — по крупному проекту, не по каждому скрипту. Подпроект обозначается тегом
области внутри записи (`scope: парсеры`, `scope: дашборд`), иначе файлов станет тридцать
и их перестанут открывать.

## Когда писать

**Сразу после того, как изменение легло.** Не в конце сессии и не «когда будет время»:
запись, отложенная до конца работы, теряет причину и цифры, а именно они и нужны потом.

**Изменение не считается сделанным, пока его нет в журнале.** Это часть определения готовности
наравне с проверкой ([[decision-gate]], пункт 5).

## Формат записи

Новые записи сверху. Одна запись — одно изменение.

```markdown
### 2026-08-02 14:52 · внесено · scope: живой трейдер
**Что:** `paper_trader.py` FEE 0.0006 → 0.0010 (6 → 10 bps)
**Почему:** справочник Binance живым запросом даёт maker и taker 10 bps, ставки 6 bps у нас нет
**Что изменилось в поведении:** будущие сделки считаются по реальной ставке; ставка добавлена
в `config_fingerprint`, в `config_history` появился четвёртый штамп
**Результат:** бумага и движок считают одни и те же деньги; доходности не добавляет
**Откат:** вернуть `FEE = 0.0006`
**Риск:** на кривой капитала шов, куски сравнивать только по штампам
```

Обязательные поля: **Что** (точное старое → новое), **Почему**, **Результат**, **Откат**.
Поля **Что изменилось в поведении** и **Риск** — когда затронута работающая система.

Статусы: `внесено` · `предложено` (ждёт «да», ещё не работает) · `откачено` (с причиной) ·
`не сработало` (важнее удач: закрывает путь, по которому не надо идти второй раз).

## Что писать обязательно, потому что git этого не видит

Git показывает диффы кода. Журнал нужен ровно для того, чего в диффах нет:

- **Причина и доказательство.** Цифра, замер, ссылка, из которых выросло решение.
- **Изменения вне репозитория:** агенты launchd, планировщики, cron, права, ключи.
- **Значения в работающих системах:** конфиги живых процессов, флаги, такты, лимиты.
- **Настройки в чужих кабинетах:** биржа, реклама, домены, хостинг, аккаунты платформ.
- **Панели и отчёты:** что теперь показывается и откуда берёт данные.
- **Откат, названный заранее.** Через месяц он не восстанавливается по памяти.
- **Предложенное и отклонённое** с причиной — иначе один и тот же спор идёт по кругу.
- **Что сломалось и как починили** — вход в, если из этого вышло правило.

Чего НЕ дублировать: построчные диффы, полные тексты файлов, вывод команд. На это есть git
и `nt_results/`. Журнал — про решения, а не про содержимое.

## Как читать, не сжигая токены

Файл растёт вечно, поэтому целиком он не читается никогда ([[token-rules]]):

- по умолчанию — **верхние 20-30 строк** (последние изменения);
- нужно про конкретную вещь — `grep` по имени файла, настройки или агента;
- нужен период — по заголовкам с датой.

## Честная граница: разные аккаунты работают только через git

Файл в `brain/` виден с другого аккаунта или машины **только если мозг запушен**.
Состояние на 02.08.2026: мозг под git (мозг под git, remote живой, проверено
`git ls-remote`), но **отстаёт от origin на 24 коммита, последний пуш 27.07.2026**.
То есть механизм есть, а синхронизации сейчас нет: всё, что написано после 27 июля, существует
только на этой машине.

Отсюда правило: **пуш мозга — часть выполнения этого протокола**, а не отдельная забота.
Пуш это действие наружу, поэтому он делается по явному «да» ([[global-rules]]), но напоминать
о нём обязан я, а не владелец.

> Смысл журнала не в отчётности. Через месяц никто не помнит, почему такт недельный, а не
> месячный, и первое, что предложит любая свежая сессия, — «давайте реже, сэкономим на
> комиссиях». Журнал отвечает на это цифрой из замера вместо спора.
