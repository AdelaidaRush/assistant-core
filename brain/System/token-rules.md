# ⚡ Token & focus rules

**Why:** распыление = и дорого, и хуже по качеству. Один сильный голос бьёт хор из десяти.

## Загрузка контекста
- В начале сессии — только. Глубже лезу, **когда строка индекса совпала с задачей**.
- Не читаю файл «на всякий случай». Нет совпадения — не гружу.
- Большие заметки читаю частями (нужный раздел), а не целиком.

## Скиллы (главное лекарство)
- ⚠️ **ОТМЕНЕНО 2026-07-23, оставлено для истории.** Здесь стояло «на домен один ведущий скилл».
 Действующее правило — [[skills-usage-rules]]: таск закрывается ВСЕМИ относящимися скиллами,
 каждый аспект своим владельцем, а конфликт двух скиллов за одну функцию выносится вопросом
 владельцу. Расхождение между этими двумя строками жило в каноне девять дней и означало, что
 два правила давали противоположные ответы на один вопрос — «сколько скиллов брать».
- Скилл вызываю, **когда он реально нужен**, а не «потому что домен похож».
- Качество визуала/текста рождается из **одного смелого видения + критики-петли**, а не из усреднения 10 мнений. Сделал → посмотрел скриншот глазами → одна правка по иерархии/контрасту/ритму → сдал.

## Почему визуал просел (диагноз)
13 дизайн-скиллов одновременно (`ui-ux-pro-max` + `frontend-design` + `design-with-taste` + `refactoring-ui` + `typography-expert` + `color-theory…` + `top-design` + `design-critic` + …) **конфликтуют** по типографике/цвету/спейсингу. Модель тратит внимание на примирение голосов, а не на исполнение. Лечение: **frontend-design ведёт, stop-slop чистит текст, design-review критикует. Точка.**

## Память
- Новое знание → атомарная заметка в мозг + строка в **карту домена**, не в L0. См. [[memory-protocol]] и [[brain-architecture]].
- Дубликаты не плодим: сначала ищу существующую заметку, обновляю её.
