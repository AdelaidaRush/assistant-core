# 🔌 Бесплатные API — сначала каталог, потом всё остальное

владелец поставил правило 30 июля 2026 вместе с: если нужны бесплатные API, мозг смотрит этот инструмент и берёт оттуда то, что полезно.

**Why:** раньше на вопрос «где взять курс валют / погоду / геокодинг» ответ рождался из головы — то предлагался платный сервис, то писался парсер сайта, который сломается через месяц. При этом готовый бесплатный API существовал почти всегда. Каталог убирает этот шаг угадывания и заодно перестаёт тратить деньги там, где платить не нужно.

**How to apply:**
1. Появилась мысль «нужен какой-нибудь API» → `python3 <каталог скиллов> <тема> --keyless`.
2. Порядок выбора: сначала `--keyless` (работает сразу, ноль регистрации) → потом API с бесплатным тарифом и ключом → и только потом платный сервис или свой парсер.
3. Перед тем как закладывать API в работу — дёрнуть его один раз и увидеть живой ответ, открыть страницу с лимитами, для клиентских данных проверить допустимость отправки на сторону.

## Что это

Репозиторий [public-apis](https://github.com/public-apis/public-apis) (сопровождает APILayer, 424k звёзд) — тот самый «API Layer», про который спрашивал владелец. Это не сервис и не SDK, а курируемый каталог в виде README. Я разобрал его в локальный JSON и обвязал поиском.

**Цифры на 2026-07-30:** 1535 API, 50 категорий, **739 работают вообще без ключа**. Крупнейшие категории: Development 146, Government 108, Finance 91, Cryptocurrency 72, Science & Math 71, Games & Comics 67, Open Data 63.

## Граница честности

Каталог это указатель, а не гарантия работоспособности. Часть проектов мертва или сменила домен, лимитов бесплатных тарифов в каталоге нет вообще — их смотреть на сайте API. «Бесплатный» сплошь и рядом означает 100 запросов в сутки, и на объёме такое решение разваливается. Поэтому проверка живым запросом обязательна до того, как API попадает в чей-то пайплайн.

Ключи от API — в `<файл кредов>`, по образцу `<файл кредов>`. Не в коде, не в репозитории, не в чате.
